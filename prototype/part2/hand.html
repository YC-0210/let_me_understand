How should the server hand environ to the application?

Between you and the server there is a real network connection. Between the server and the application there is not — they are the same running program, and the call is an ordinary function call. Four ways to draw that were built and compared; this is the one that was chosen.

work fills · travel moves

WHAT WAS DECIDED

One line mark for both channels. The word underneath says which kind it is — a network connection or a function call. The mark carries channel; the name carries what kind.

WHAT IT COSTS

The drawing ends symmetrical, so at a glance the application looks as far away as the server does. The word is doing work the mark is not. Three rejected alternatives — a second kind of line, the application drawn inside the server, and no third place at all — are in git history.

WHAT IT DOES TO THE SPEC

Nothing new. No ADR. §1 already defines a line as a channel between two places; part 1 simply never had more than one kind of channel, so the definition was never tested.

NOT DRAWN YET

start_response. The application calls it to hand status and headers back to the server while the application is still running, and the server parks them in headers_set until it builds the response. That is a thing genuinely at rest inside a place — which is where the held disc belongs, and it is the only place in part 2 that earns it.

Throwaway. Nothing here is captured — the body reads Hello world from Flask! because that is what the article's flaskapp.py returns, but no server has been run yet. This page settled one thing: the mark between the server and the application. Delete it once the real drawing exists.
