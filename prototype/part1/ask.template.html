TCP connection
“Before your browser can send a HTTP request though, it first needs to establish a TCP connection with the Web server.” That is everything the article says about it, so it is everything the picture says about it.

beyond the article

TCP gives two programs an ordered, reliable stream of bytes. Either side can write into it, and whatever arrives comes out in the order it was written.

A connection is identified by four things: both addresses and both port numbers. Your browser never picked its own port number — the operating system handed it one.

The programming interface for all of this is called a socket.

Part 3 of this same series takes sockets apart properly: creating one, binding it to a port, listening, and accepting connections.

Everything below travels over that connection.

beyond the article

GET asks for something. The ones you will meet next:

  • POST — send data to the server
  • PUT — replace something
  • DELETE — remove something
  • HEAD — like GET, but the server sends only the top part, no body

This particular server never looks at the method. Sending it DELETE gets you the same “Hello, World!” — which was checked by really sending it.

beyond the article

HTTP/1.0 opened a fresh TCP connection for every single request and closed it after the response.

HTTP/1.1 keeps the connection open by default, so several requests can reuse one connection.

HTTP/2 sends the same information in a binary form and can interleave many requests over one connection.

HTTP/3 changes the foundation underneath: it runs over QUIC, on UDP, instead of TCP.

Worth noticing: this server writes HTTP/1.1 into every response, but then closes the connection after answering once — which is HTTP/1.0 behaviour.

beyond the article

200 is one of many. The first digit places a code in a family:

  • 1xx — information, keep going
  • 2xx — it worked
  • 3xx — look somewhere else
  • 4xx — something was wrong with the request
  • 5xx — something went wrong inside the server

Ones you have met: 301 Moved Permanently, 304 Not Modified, 403 Forbidden, 404 Not Found, 500 Internal Server Error.

Now look at what you have been doing: you asked this server for pages that do not exist, and it answered 200 OK every time. An honest server would have said 404. Choosing the right code is the server's job, and this one never does it.
