# The trace mark

Adds an eighth mark to the visual language: a **trace** — a faint dashed line, in the
colour of whatever travelled, marking a path something has already taken.

Without it a finished exchange showed only its last state, so the reader could not see
the whole thing at once — the property the project exists to provide. The alternative,
leaving the moving dots on screen, would have broken the grammar rule that a disc exists
only while travelling.

## Consequences

A trace is **history, not structure**: it persists after the channel it used has closed,
which is why the drawing can show a closed connection and the exchange that happened over
it at the same time. It carries the label and the door for the thing that travelled, so
the request stays reachable after the request is over.
